# ESP32 桌邊藍牙控制器

ESP32-C3 核心板 + Display-Keypad 擴充板(0.96" 160×80 螢幕 + 五向鍵),橫向使用:**螢幕在左、按鍵在右**。
韌體 MicroPython,手機端是 Android 配套 App(Kotlin)。

```
deskctl/
├─ firmware/   板子上的 MicroPython 程式 + font12.bin(繁中點陣字型, 15,192 字)
├─ android/    手機端 App 原始碼(Android Studio / GitHub Actions 皆可打包)
├─ tools/      upload.sh / upload.bat(上傳韌體)、make_font.py(重製字型)、sim/(桌面模擬與測試)
└─ .github/workflows/build-apk.yml   推上 GitHub 就自動打包 APK
```

## 為什麼需要手機 App?

純 HID 藍牙(像藍牙鍵盤)只能「送按鍵」, 讀不到手機現在播什麼歌、播到幾秒、電量與音量。
要在螢幕顯示這些、而且做到精準 ±5 秒跳轉, 手機端必須有 App 讀取媒體工作階段並回報。
通訊用標準的 Nordic UART 服務(BLE), 訊息為一行一筆 JSON(見最後面)。

## 1. 接腳(已確認)

擴充板是**旋轉 180° 疊在核心板上**, 擴充板第 n 腳接到核心板第 33−n 腳(電源腳 1/2/7/8/15/16 與 SPI 腳 SDA/SCK 都能對上, 可交叉驗證):

| 功能 | 擴充板腳 | 核心板腳 | GPIO |
|---|---|---|---|
| **上**(橫放時) = 電路圖 UPKEY | 4 | 29 | 8 |
| **右** = 電路圖 LKEY | 3 | 30 | 9 (BOOT 鍵) |
| **中** = CENTER | 5 | 28 | 4 |
| **左** = 電路圖 DWKEY | 6 | 27 | 5 |
| **下** = 電路圖 RKEY | 23 | 10 | 13 |
| 螢幕 BL / CS / DC / RES | 9 / 10 / 11 / 12 | 24 / 23 / 22 / 21 | 11 / 7 / 6 / 10 |
| 螢幕 SDA(MOSI) / SCL(SCK) | 13 / 14 | 20 / 19 | 3 / 2 |

要改腳位只要改 `firmware/config.py`。

**注意**
- 板子橫放(按鍵在右)時, 實體方向比電路圖上的名稱轉了 90°, 所以上述對應是「橫放後的方向」。若仍不對, 在 `config.py` 對調 `PIN_*` 數字即可, 校正畫面最下面會顯示你按到哪個鍵。
- **開機/重啟的瞬間不要按住「右」鍵**(GPIO9 = BOOT, 會進下載模式)。中央長按 5 秒重啟時放手即可。
- GPIO13 同時接板上 LED, 若「右」鍵偶爾誤判, 請告訴我, 可改軟體消除。
- GPIO11 在部分核心板是 flash 電源腳, 程式會自動嘗試; 失敗只代表無法關背光(常亮), 不影響使用。

## 2. 燒錄與上傳韌體(需要一台電腦做一次)

1. 下載 MicroPython 的 **ESP32_GENERIC_C3** 韌體(micropython.org/download/ESP32_GENERIC_C3/), 用 `esptool` 燒錄:
   `esptool.py --chip esp32c3 --port COM5 erase_flash` 然後 `esptool.py --chip esp32c3 --port COM5 --baud 460800 write_flash --flash_mode dio 0 ESP32_GENERIC_C3-xxxx.bin`
   **一定要加 `--flash_mode dio`**: 這塊板子的 SPI Flash 在 QIO 模式會和 GPIO12/13 衝突, 而「右」鍵就接在 GPIO13。
   (USB-C 接板上的 CH343P 那顆; Windows 需要 CH343 驅動)
2. `pip install mpremote`, 然後執行 `tools/upload.sh COM5`(Windows 用 `tools\upload.bat COM5`), 會把 `firmware/` 全部傳上去並重啟。
3. 第一次開機會出現**螢幕校正畫面**: 上=轉方向、**右=換面板型號(偏移)**、下=反相、左=RGB/BGR 色序, 調到「文字正、按鍵在右、R/G/B 色塊顏色對」後按中央儲存。之後可在 目錄→快捷設定→螢幕方向校正 重做。

## 3. 手機 App(Android 8.0+)

**方法 A:不用裝 Android Studio**
1. 把整個 `deskctl` 資料夾推到你自己的 GitHub repo(私人的也行)。
2. 到 repo 的 Actions → Build APK → Run workflow, 完成後下載 artifact 裡的 `app-debug.apk`, 傳到手機安裝。

**方法 B:** 用 Android Studio 開 `android/` 資料夾, Build → Build APK。

App 有三個分頁:
- **主頁**(平常只用這頁): 大狀態卡(灰=已停止、橘=連線中、綠=已連線 + 連線時間)、一顆**啟動/停止**按鈕、**重新連線**、目前播放的歌。初次設定沒做完時會出現橘色提醒。
- **記錄**: 所有連線、斷線(含狀態碼)、指令與錯誤集中在這裡, 可**複製 / 分享 / 清除 / 只看異常**, 重開 App 還在。回報問題時請按「複製」貼給我。
- **設定**: 「初次設定」三項(授權、通知存取、背景執行)做完會自動收合成「✔ 初次設定已完成」; 另有偏好(開機自動啟動、開啟 App 自動啟動)、控制器管理(重新同步、忘記重新搜尋)、關於。

首次設定(到「設定」分頁依序按):
1. 授權藍牙與通知。
2. 開啟「通知存取」並勾選「桌邊控制器」(這是 Android 讀取其他 App 歌名/進度的唯一合法管道)。Android 13+ 若灰色不能勾: 按下方「允許受限設定」進 App 資訊 → 右上 ⋮ → 允許受限設定。
3. 把電池設定改成「不受限制」, 避免系統在背景殺掉服務。
之後回「主頁」按**啟動**即可。板子要先通電; App 會自動搜尋 `DeskCtl` 並記住, 之後斷線會自動重連, 手機重開機也會自動啟動(啟動過一次後)。常駐通知上也有「重新連線」「停止」按鈕, 不用開 App。

連上後右上角藍牙圖示變**綠色**, 首頁時間會自動校準。

## 4. 操作總表

手勢: **短按** / **雙擊** / **長按**(>0.6 秒) / **超長按**(5 秒)

### 全域
| 操作 | 功能 |
|---|---|
| 中央長按 | 開啟目錄(目錄中再長按 = 回原頁) |
| 中央連按 3 下 | **回首頁**(已在首頁則回到剛才離開的頁面, 可來回切換; 貪吃蛇等遊戲中無連按判定, 請用中央長按進目錄) |
| 中央長按 5 秒 | **重啟整台裝置**(按住 1.8 秒後螢幕顯示倒數) |
| 方向鍵長按 5 秒 | **該頁重設 / 重新同步**(首頁、音樂=向手機重新要資料; 碼表=歸零; 遊戲=重新開始) |
| 左 / 右 短按 | 非音樂頁: 依「快捷清單」切換前/後一頁(首頁→右→碼表) |

### 目錄
上下選擇 · 中央進入 · **右鍵 = 加入/移出★快捷清單** · 左鍵返回。項目: 首頁、碼表、音樂、遊戲、捷徑、說明書、快捷設定。

### 狀態欄(右上角, 由右至左)
時鐘(預設不顯示秒) · 藍牙(綠=已連線) · ▶ 手機正在播放音訊 · 碼表圖示(計時中)。標題太長會自動截斷。

### 首頁
(預設 12 小時制並顯示秒; 首頁與狀態欄的秒數可分開設定)
時間、日期、藍牙狀態、手機電量(含充電)、正在播放的歌(含播放/暫停圖示)。時間由手機校準。
**首頁也能控制音樂**(不顯示完整音樂畫面, 調音量時會跳出音量提示框):
中央 播放/暫停 · 中央雙擊 靜音 · 上/下 音量(可按住) · 上雙擊 隨機 · 下雙擊 循環 · 左/右雙擊 上一首/下一首 · 左/右長按不放 連續倒轉/快轉。
(左/右**短按**仍是快捷切換頁面, 所以首頁沒有單擊 ±5 秒; 要單擊快轉請進音樂頁)

### 碼表(背景持續計時, 計時中所有頁面右上角都有碼表圖示)
中央 開始/暫停 · 上 記圈 · 下 重設(需先暫停) · 下雙擊 隨時強制重設 · **上/下長按 = 捲動圈數清單**(新記圈會自動跳到最新)。超過 1 小時改用 h:mm:ss 排版,不再重疊。

### 音樂
| 操作 | 功能 |
|---|---|
| 中央短按 | 播放 / 暫停 |
| **中央雙擊** | 靜音 / 取消靜音(長按已留給目錄) |
| 右短按 / 左短按 | 快轉 +5 秒 / 倒轉 −5 秒 |
| 右雙擊 / 左雙擊 | 下一首 / 上一首 |
| 右 / 左 長按不放 | 連續跳轉 |
| 上 / 下 短按(可按住) | 音量 + / − 一格 |
| 上雙擊 | 隨機播放 開/關 |
| 下雙擊 | 循環模式: 不循環 → 清單循環 → 單曲循環 |

螢幕顯示: 歌名(太長會捲動)、歌手·專輯、進度條、目前/總時間、控制與隨機/循環狀態、音量、輸出裝置圖示(🎧 綠=藍牙耳機、藍=有線、📱=手機喇叭)、右上角時間。
(跳轉秒數、音量步進可在快捷設定調整)

### 遊戲
清單上下選、中央開始; 遊戲中**中央雙擊回清單**。
- 貪吃蛇: 方向鍵轉彎, 穿牆, 中央暫停, 越吃越快
- 1A2B: 左右選位、上下**單按**改數字、中央送出; 紀錄超過 5 筆時**上下長按**翻看舊紀錄
- 隨機取數: 設定範圍(預設 000~999, 三位數各自可改)與個數(兩位數), 最右格切換「重複/不重複」; 中央抽, 結果太多時上下(單按或長按)捲動, 中央再抽一次, 雙擊回設定; 設定會記住
- 骰子猜大小: 上 押大(11–17)、下 押小(4–10)、左右調下注; 豹子通殺

### 說明書
上下翻頁(17 頁, 含按鍵位置圖解)。

### 省電(閒置時自動)
| 閒置時間 | 狀態 |
|---|---|
| 未達「變暗時間」(預設 1 分鐘) | 背光=「背光亮度」(預設 80%) |
| 「變暗時間」~「低亮度時間」(預設 1~10 分鐘) | 背光減半 |
| 超過「低亮度/時鐘待機」時間(預設 10 分鐘) | 背光 15%; **沒播歌時自動切到首頁當大時鐘**, 按鍵後回到原頁(遊戲中不換頁) |
| 「自動熄屏」時間到(預設永不; 可選 30 秒~2 小時) | 背光 0 **並讓面板進入 Sleep**(之前只是畫面變綠、背光仍亮, 已修正) |
低亮度/熄屏時第一下按鍵只負責喚醒; 手機開始播放也會喚醒。「閒置省電」可關閉。
**深度睡眠(實驗, 預設關)**: 低亮度/熄屏時主迴圈改用 `machine.lightsleep`, 更省電, 但可能影響藍牙連線與 USB 序列埠(Thonny 會斷線), 若連線變不穩請關掉。若 GPIO11 其實是核心板的 Flash 電源腳而無法 PWM, 調光會自動退回開/關。

**背光無法控制(已實測)**: 這塊板子的背光接在 GPIO11(ESP32-C3 的 VDD_SPI 腳), 拉高拉低都沒有效果, GPIO0/1/12 也不是背光, 所以背光一直是亮的。因此 `config.py` 的 `BL_CONTROL` 預設 `False`: 不做調光、設定裡也不顯示「背光亮度」「變暗時間」。閒置時仍有: 低亮度/時鐘待機(沒播歌時切成首頁大時鐘、CPU 放慢)與自動熄屏(面板 Sleep, 畫面全黑)。
若想真的省背光電, 只能改硬體: 把擴充板的 LCD_BL 線改接到可用的 GPIO(例如焊線到 GPIO0), 再改 `PIN_BL` 並把 `BL_CONTROL = True`。**不建議燒 eFuse 讓 GPIO11 變一般腳位**(不可逆, 且在 VDD_SPI 供電給 Flash 的板子上會讓板子變磚)。

### 快捷設定
時間制 12/24 · 首頁顯示秒 · 狀態欄顯示秒 · 閒置省電 · 低亮度/時鐘待機 · 自動熄屏 · 深度睡眠(實驗) · 跳轉秒數 · 音量步進 · 重新連線藍牙 · 螢幕方向校正 · 還原設定

## 5. 新增功能區/遊戲
1. 在 `firmware/` 新增 `g_xxx.py`, 寫一個繼承 `app.Page` 的類別(可參考 `g_dice.py`, 約 100 行)。
2. 在 `firmware/registry.py` 的 `PAGES` 加一行 `("id", "名稱", "g_xxx", "類別名", "game")`(群組 `main` 會出現在目錄, `game` 出現在遊戲清單)。
3. 用 `tools/upload.sh` 上傳。

### 捷徑(手機設定、板子上一鍵執行)
在手機 App 的「捷徑」分頁新增捷徑, 控制器目錄裡的「捷徑」頁就會顯示同樣的名單, 上下選、**中央執行**, 手機會依序做完並回報「完成 / 失敗」。
步驟類型: 開啟 App · 開網址(可指定瀏覽器, 如 Brave) · 等待幾秒 · 媒體鍵(播放/暫停/下一首/上一首) · 點擊畫面位置 · 點擊含某文字的按鈕 · 按返回 · **重新整理目前頁面**(找「重新載入」按鈕, 找不到就下拉) · 喚醒螢幕 · **確保播放中**(背景開的影片常卡在開頭或被自動靜音; 每輪: 點「取消靜音」並解除系統靜音 → 送播放鍵 → 用真實觸控點一下播放器位置(算使用者手勢), 最多 3 輪, 偵測到有聲音就結束; 失敗時會把畫面上讀到的項目寫進「記錄」(標籤「畫面內容」), 貼給我就能對症調整; 位置預設 50%,23%, 可用準星重選) · **點第一部影片**(在搜尋結果頁找第一個大的可點項目, 略過廣告/Shorts, 找不到就點畫面 50%,38%)。內建範本:
- **開啟 App 並自動播放**(如 Samsung Music): 開 App → 等 4 秒 → 送播放鍵。
- **重新整理網頁**: 喚醒螢幕 → 重新整理。依序嘗試: 畫面上的「重新載入」鈕 → 打開瀏覽器選單(⋮)點「重新載入」→ 先捲到頂再慢速下拉。過程寫在「記錄」。瀏覽器卡住時從控制器按一下即可(需無障礙服務, 手機需已解鎖)。
- **用瀏覽器開網址**: 例如用 Brave 開某部 YouTube 影片或播放清單的連結(最穩定)。
- **YouTube 搜尋並播放第一部影片**: Brave 開搜尋結果 → 等 6 秒 → 點擊畫面 (50%,40%)。這一步靠「點位置」, 不同手機、有沒有廣告/Shorts 位置都不同, 請按「▶ 測試」調整百分比。
**點擊位置不用自己算座標**: 編輯「點擊畫面」步驟時按「在畫面上選取」, App 會退到背景, 你切到目標畫面(例如 YouTube 搜尋結果), 拖曳紅色準星到要點的位置按「確定」, 就會自動填入橫%、縱%(0,0=左上角, 100,100=右下角)。需要「顯示在其他 App 上層」權限。
手機上按「▶ 測試」可不用板子直接試跑, 過程寫在「記錄」分頁。
**需要的權限(設定分頁, 皆為選用)**:
- 「顯示在其他 App 上層」: Android 10+ 禁止背景直接開 App, 有這個權限(或無障礙服務)才能從背景開啟。
- 「無障礙服務」: 只有「點擊畫面 / 點擊文字 / 返回」步驟需要。它不讀取也不上傳畫面內容。改版後(v1.3.4)無障礙設定有更新: 請把「桌邊控制器」無障礙服務關掉再開一次, Chrome 系瀏覽器(Brave)才會把網頁內容提供給它。Android 13+ 若灰色不能開: App 資訊 → ⋮ → 允許受限設定。
限制: 沒有無障礙就點不到畫面; 不同音樂/瀏覽器 App 對「播放鍵」「自動播放」的反應不一(例如瀏覽器可能擋自動播放)。協定: 手機→板子 `{"k":"acts","l":[名稱…]}`、`{"k":"act","s":"run|done|fail|busy","n":名稱,"m":訊息}`; 板子→手機 `{"c":"run","i":編號}`。
新增步驟類型: 在 `ShortcutFeature.step()` 加一個分支, 並在 `ShortcutsPage` 的選單加一項。

### 系統總覽(控制器自己看即時狀態)
控制器目錄的「系統總覽」不用開手機 App 就能看(每秒更新), 上下切換 4 頁: **總覽**(左手機: 電量/網路/背景/RAM; 右開發板: 已運作/RAM 剩餘%/藍牙/晶片溫度)、**運作**(韌體版本、已運作、目前頁面、螢幕狀態、重啟原因)、**記憶體**(已用%與剩餘、最近約 2.5 分鐘的剩餘記憶體趨勢圖、歷史最低、儲存空間)、**連線**(藍牙狀態、連線/斷線次數、上次連線時長、手機資料多久前)。手機資訊來自手機每 10 秒的回報, 手機沒連線時顯示「--」。晶片溫度在部分 MicroPython 版本沒有則顯示 --。

### 比分板(MLB / NBA / CPBL)
- 手機 App「比分」分頁: 選聯盟與日期(台灣時間) → 點「追蹤」加入(最多 8 場), 可調整順序/移除。手機在背景抓資料傳給控制器的「比分板」頁(控制器在比分頁時 8 秒更新, 否則有比賽進行 30 秒、無則 3 分鐘)。
- 控制器: **左右鍵切換比賽、上下鍵切換主畫面/細節**。棒球: 隊伍、比分、上/下半局、壘包、好壞球、出局數(細節: 每局得分、安打、失誤、打者、投手)。籃球: 隊伍、比分、節數與計時(細節: 犯規、暫停、罰球加成、每節得分)。
- 資料來源: MLB=statsapi.mlb.com(官方); NBA=cdn.nba.com(失敗時改 ESPN, 無犯規資料); **CPBL=cpbl.com.tw 官網, 無公開介面, 屬實驗性**, 網站改版可能失效, 失敗原因在「記錄」分頁(標籤 CPBL)。NBA 官方 CDN 與 CPBL 的格式尚未在實機驗證。
- MLB 即時畫面額外顯示打者打擊率與當場「安打-打數」、投手投球數(細節頁還有投球局數與責失分); 未開賽的比賽顯示日期與開賽時間; 賽後細節頁顯示勝投、敗投、救援投手。NBA 賽程會合併官方資料與 ESPN, 季前賽也找得到。
- 協定: 手機→控制器 `{"k":"games","l":[[聯盟,客,主],...]}`、`{"k":"score","i":欄位,...}`; 控制器→手機 `{"c":"sc","on":1|0}`。

### 手機訊息(通知轉發)
- 手機 App 把新通知(LINE、簡訊、Email…)轉發到控制器的「手機訊息」頁。**總覽**: 上下選、中央看內容、**長按左=刪除此則、長按右=刪除全部**; **內容中**: 上下捲動、**長按左=刪除此則、長按右=標記/解除標記**。**已標記(黃色方塊)的訊息不會被刪除**(全刪會跳過、手機端清掉通知也不會帶走、超過 12 則時也最後才丟), 要刪必須先長按右解除標記。粉紅點=未讀。標記只存在記憶體, 控制器重開機會清空。新訊息會跳提示、喚醒螢幕、狀態欄出現信封圖示(可在快捷設定關閉); 在手機上把通知滑掉/已讀, 控制器上也會跟著消失。
- 需要「通知存取」權限(與音樂控制共用)。手機 App「設定 → 手機訊息」要先按「選擇要轉發的 App」勾選(**只轉發有勾選的 App**, 沒勾任何 App 就不會轉發), 另可關閉轉發、**隱藏內容**(只顯示 App 名稱)。所有選 App 的清單(轉發、清理保護、捷徑)都有搜尋欄, 輸入 App 名稱即可篩選。常駐通知、播放器、進度條、群組摘要與本 App 的通知不轉發。
- 協定: 手機→板子 `{"k":"msg","i":編號,"a":App,"t":標題,"x":內容}`、`{"k":"msgrm","i":編號}`。控制器只在記憶體保留最近 12 則, 重開機即清空。
- 目錄若曾在手機端自訂過順序, 控制器新增的頁面(如「手機訊息」)會在連線時自動補進目錄(放在「設定」前面); 你刻意隱藏過的頁面不會被加回來。

### 手機清理(結束背景 App / 清快取 / 清最近使用)
- 控制器「手機狀態」頁: **中央 = 結束背景 App + 清本 App 快取**; **中央雙擊 = 再加清除最近使用清單**。結果會跳提示(例如「完成 清理 釋放約 300MB」)。手機 App「狀態」分頁底下也有同樣的按鈕, 捷徑也新增步驟「結束背景 App + 清快取」「清除最近使用的 App」與範本「手機清理」。
- 做的事: ① 結束背景 App(`killBackgroundProcesses`), 自動保護: 本 App、有媒體工作階段的 App(音樂/Brave 影片)、輸入法、桌面, 以及你在「選擇清理時要保護的 App」勾的; ② 清除本 App 快取; ③ 用無障礙服務開啟最近工作並點「全部關閉」(找不到按鈕會把畫面內容寫進記錄)。
- **做不到的**: Android 不允許第三方 App 清除「別的 App 的快取」, 也不能真正「釋放系統快取」; 系統本來就會自己回收記憶體, 結束背景 App 的效果是暫時的, 重開的 App 反而會比較慢、也更耗電。建議只在手機卡頓時用, 不要排程連續執行。清最近使用在不同品牌(Samsung「全部關閉」/ Pixel「全部清除」)按鈕名稱不同, 我只列了常見名稱。

### 背景運作(手機放一旁、App 沒開)
- 連線由前景服務(通知列常駐)負責, **不需要打開 App 畫面**; 滑掉 App 也不影響, 只有按「停止」或系統強制結束才會中斷。設定分頁有「連線時保持 CPU 不休眠」(預設開), 讓螢幕關閉時計時與藍牙也不被凍結; 代價是較耗電。
- 音樂控制、電量、時間、狀態回報在螢幕關閉/上鎖時都能運作。
- **捷徑(開 App、點擊、重新整理)需要手機螢幕已解鎖**: 上鎖時只能喚醒螢幕, 無法代為解鎖。建議放著用的時候把螢幕休眠時間調長, 或用「喚醒螢幕」步驟 + 無鎖定畫面。
- 各家系統的省電機制不同(Samsung 的「休眠中的 App」、Brave 被系統凍結等), 請在設定分頁完成「允許背景執行」, 並把本 App 從休眠清單移除。以上我都沒有實機驗證。

### 手機狀態、控制器狀態與目錄順序
- **控制器「手機狀態」頁**(4 個子頁, 上下切換, 用顏色表示好壞: 綠=正常 黃=注意 紅=有問題 灰=資料過期): 電源(大字電量、電量條、充電方式、溫度/電壓、過熱警示)、連線(網路與 Wi-Fi 訊號、手機藍牙、螢幕、與控制器連線)、背景(一句話結論「背景運作正常/需留意/可能被限制」+ 省電模式、Doze、背景限制、待機分組)、資源(RAM 條、App 記憶體/快取、儲存剩餘)。每 10 秒更新; 快捷設定的「重新同步」可立即要求手機重送。
- **手機 App「狀態」分頁**: 手機同樣的數據, 加上控制器的版本、已運作時間、目前頁面、剩餘/已用記憶體(含趨勢圖)、藍牙連線/斷線次數。
- **目錄順序**: 手機 App「設定 → 控制器目錄順序」可上下移動、隱藏頁面、☆/★ 設定左右鍵快速切換; 按「儲存並送出」, 連線時會自動送到控制器並存起來(「首頁」固定第一個、「設定」一定保留)。

### 手機 App 新增功能(模組化)
手機端每一塊功能都是一個 `Feature` 模組(`android/app/src/main/java/tw/deskctl/`): `TimeFeature`(校時)、`BatteryFeature`(電量)、`MediaFeature`(音樂)。`BridgeService` 只負責連線與收發, 不用改。
1. 新增 `XxxFeature.kt`, 繼承 `Feature(host)`, 覆寫需要的: `start()/stop()`(資源)、`onReady()`(連線完成時送出完整狀態)、`onTick(n)`(每秒)、`onCommand(c, o)`(認領控制器傳來的 `{"c":"..."}` 指令, 處理了回傳 true)、`info()`(主頁顯示的一行說明)。送資料用 `host.send(JSONObject().put("k","xxx")...)`, 內容沒變就不重送用 `host.sendIfChanged`。
2. 在 `Features.kt` 的 `registry` 加一行 `FeatureEntry("xxx", "名稱") { h -> XxxFeature(h) }`。
3. 韌體端: `firmware/state.py` 的 `apply()` 加對應 `k == "xxx"` 處理, 頁面用 `app.link.send({"c":"..."})` 發指令(新頁面做法見上一節)。
4. 要加「設定」: 在 `Prefs.kt` 加一對 getter/setter, 再到 `MainActivity.buildSettings()` 加一個開關。要記錄就用 `AppLog.i/w/e("標籤", "訊息")`, 會自動出現在「記錄」分頁。

## 6. 已知限制(請先知道)
- **我無法在實體板子與手機上測試**。韌體的畫面排版、手勢、頁面邏輯與藍牙封包處理都在桌面模擬器驗證過(`tools/sim/test_all.py`、`test_ble.py` 與畫面截圖), 但 ST7735 的顯示方向/色序、GPIO13 與 LED 共用、Android App 的編譯與實機行為都沒有實測。Android 專案在我的環境無法連到 Google 的套件庫所以**未編譯過**, 第一次打包若出現編譯錯誤請把錯誤訊息貼給我。
- 隨機/循環模式是否生效取決於音樂 App 是否開放(本地播放器多半支援, Spotify、YouTube Music 可能忽略); 無法讀回時, 螢幕顯示的是裝置自己記的狀態。
- 沒有媒體工作階段(沒開任何音樂 App)時, 播放/下一首會改送系統媒體鍵。
- 連線沒有配對密碼, 範圍內的其他 BLE 裝置理論上也能連上控制音量; 只連一台時別人連不進來。
- 手機端同時只控制一個音樂 App: 會監聽所有媒體工作階段, 誰開始播放就切過去(例如 Samsung Music 暫停中、Brave 的 YouTube 開始播放, 就改控制 Brave); 都沒在播時控制最後播放過的。Brave/Chrome 網頁影片要有媒體通知才抓得到。

## 7. 通訊協定(供除錯)
UUID 與 Nordic UART 相同(可用 nRF Connect 看): Service `6E400001-…`; 手機→板子寫入 `…0002`; 板子→手機通知 `…0003`; 每行一筆 JSON、以 `\n` 結尾。
- 手機→板子: `{"k":"time","t":unix秒,"z":時區分鐘}` · `{"k":"batt","p":83,"ch":1}` · `{"k":"track","t":歌名,"a":歌手,"b":專輯,"d":毫秒,"app":App名}` · `{"k":"play","s":0停/1播/2暫,"p":位置毫秒,"v":速度×100}` · `{"k":"vol","v":9,"m":15,"mu":0}` · `{"k":"route","r":"bt|wired|spk","n":名稱}` · `{"k":"mode","sh":0/1,"rp":0/1/2}` · `{"k":"ping"}` · `{"k":"sys",pl,t,v,th,nt,wf,bt,sc,ps,ds,bk,br,ra,rf,ap,ca,sf}`(手機狀態) · `{"k":"layout","m":[頁面id…],"r":[快切id…]}` · `{"k":"msg",…}` · `{"k":"msgrm","i":編號}`
- 板子→手機: `{"c":"pp"|"next"|"prev"|"mute"|"sync"|"pong"}` · `{"c":"seek","d":±毫秒}` · `{"c":"vol","d":±格}` · `{"c":"shuffle","v":0/1}` · `{"c":"repeat","v":0/1/2}` · `{"c":"run","i":編號}` · `{"c":"clean"|"clean2"}` · `{"c":"stat",ver,up,mf,ma,pg,cn,dc,lu}`(每 10 秒) · `{"c":"pages","l":[[id,名稱]…]}` · `{"c":"layout","m":[…],"r":[…]}`(連線時與變更時)

## 8. 疑難排解
| 現象 | 處理 |
|---|---|
| 畫面全黑 | 確認背光(GPIO11); 到校正畫面試「上」換方向、「下」反相 |
| 畫面鏡像/顛倒 | 目錄→快捷設定→螢幕方向校正, 按「上」直到正確 |
| 紅藍顏色反了 | 校正畫面按「左」切換 RGB/BGR |
| 畫面歪斜(斜體)/偏移/邊緣雜點 | 進校正畫面按「右」切換面板型號(偏移規格), 直到外框四邊完整、不歪斜 |
| 想重新校正 | **開機(插上電)時按住中央**, 就會進入校正畫面(畫面左上會顯示版本號 v0.6, 可用來確認檔案是否上傳成功) |
| 已存過設定, 進不了校正畫面 | 電腦執行 `mpremote fs rm :settings.json` 後重啟, 就會重新校正 |
| 開機後出現錯誤文字 | 8 秒後會自動重啟; 用 `mpremote` 連線看完整錯誤訊息 |
| 圖示一直是灰色 | 手機 App 沒啟動 / 藍牙沒開 / 板子沒通電; 黃色 = 已連上但 App 沒回應(重新按③) |
| 藍牙連一下斷一下 | 看手機 App 主畫面最下方的「連線日誌」(會寫斷線代碼: 8=訊號逾時、19=裝置端斷開、133=連線失敗); 板子的 快捷設定→藍牙診斷 會顯示連線/斷線次數與上次連線秒數 |
| 歌名捲太快/太慢 | `config.py` 的 `MARQUEE_MS_PER_PX`(預設 50, 數字越大越慢)、`MARQUEE_HOLD_MS`、`MARQUEE_GAP_PX` |
| 出現 MemoryError | 序列埠會印 `mem free`; 偶發會自動整理後繼續, 10 秒內連續 8 次才重啟。若常發生請把 `mem free` 數字給我 |
| 沒有歌名 | 沒開「通知存取」, 或沒有任何音樂 App 在播放 |
| 右鍵不靈 | GPIO13 與 LED 共用, 回報我 |
